# Contribuir

1. Crear una rama corta desde `main`.
2. Mantener el aviso “Propuesta conceptual no oficial”.
3. No incorporar datos reales, logos ni imágenes sin autorización escrita.
4. Ejecutar `pnpm check` antes de solicitar revisión.
5. Explicar en el PR qué problema resuelve, qué cambió y cómo se verificó.

La UI debe seguir `.agents/skills/design-flm-impact-portal/SKILL.md`. Priorizar cambios pequeños que completen un flujo antes que sumar pantallas aisladas.
